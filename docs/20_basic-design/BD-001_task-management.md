# BD-001 ページに関連するタスク管理

## 1. 概要

閲覧ページに関連するタスクを端末内で管理し、対象ドメインの再訪時に未完了タスクを通知する。UI には Vue 3 を提案し（ADR-0002）、データは拡張機能オリジンの IndexedDB に保存する（ADR-0003）。対象ドメインの判定には同梱する Public Suffix List（PSL）を使う案とする（ADR-0004）。

FR-004 と NFR-SEC-001 に従い、タスク情報を表示する登録・リマインド画面は、閲覧ページとは独立した拡張機能ウィンドウに配置する。本書と ADR が承認されるまでは詳細設計・実装に進めない。残る設計上の未決事項は詳細設計で検討し、基本設計・ADR の前提が変わる場合は該当文書に差し戻して再承認を受ける。ライブラリの同梱物と配布条件は採用・導入前に確認する。実装を要する検証は後工程で実施し、不合格の場合は設計に差し戻す。

## 2. 画面設計

### 2.1 画面一覧

| 画面 ID | 画面名           | コンテキスト               | 対応 FR        |
| ------- | ---------------- | -------------------------- | -------------- |
| SCR-01  | タスク登録       | 独立した拡張機能ウィンドウ | FR-002         |
| SCR-02  | タスク一覧・編集 | popup                      | FR-003、FR-004 |
| SCR-03  | リマインド       | 独立した拡張機能ウィンドウ | FR-004         |

- SCR-01: タスク名、対象 URL・ドメイン、期限、詳細、画像と、撮影範囲の選択・保存・取消を表示する。タスク名は必須、画像は最大10枚、1枚5,000,000バイトまでとする。保存失敗時は理由と入力内容を表示する。
- SCR-02: 拡張機能アイコンから開き、期限順の一覧、完了状態・ドメインの絞り込み、編集、完了・未完了の変更、削除確認、タスク単位・ドメイン単位のリマインド停止を提供する。期限超過は端末の現地日付で判定する。画像の追加・個別削除・差し替えは編集画面で行い、タスクの保存時に確定する。
- SCR-02 の画像撮影中は、編集内容を端末内の一時データとして保持し、popup が閉じても撮影後に編集を再開する。編集の保存または取消時に一時データを削除する。
- SCR-02 の削除確認にはタスク名と画像も削除される旨を表示し、「削除」と「キャンセル」を選べるようにする。削除に失敗した場合は成功扱いにせず、理由を表示する。
- SCR-03: 対象の未完了タスクの一覧、閉じる操作、停止期間の設定・変更・解除を表示する。元のタブごとに1画面とし、自動表示時は前面に出す。
  SCR-01・SCR-03 は拡張機能が独立ウィンドウとして開く案とする（REF-021）。ページ内には埋め込まず、タスク内容・画像をページの DOM に表示しない。content とページは DOM を共有するため（REF-009）、content に渡す情報を撮影・ページ操作に必要なものに限定し、機密情報を渡さない（REF-010）。

### 2.2 画面遷移

1. 対応ページで Ctrl+Shift+Y を押す → SCR-01 → 保存または取消で閉じる。
2. 拡張機能アイコン → SCR-02 → タスクを編集・完了・削除、またはリマインド停止期間を設定する。
3. 対象ページの読み込み・再読み込み・URL が変わるページ内遷移 → 対象の未完了タスクがあれば独立ウィンドウで SCR-03 を表示または更新する。同じ元のタブでは画面を重複させず、表示時は前面に出す。元のタブを閉じた場合は対応する SCR-03 も閉じる。
4. 対象タスクがない場合はリマインド画面を表示しない。SCR-03 は閉じる操作を提供する。
5. SCR-02 の編集で撮影を選ぶ → 編集途中の内容を一時保存 → 対象 URL を新しいタブで開く → そのタブで拡張機能アイコンを操作して一時権限を付与 → 撮影用の独立した拡張機能画面で撮影し、撮影後に編集を再開する案とする。一時保存に失敗した場合は撮影に進まず、理由を表示する。画面の起動・再開方法は詳細設計と実機検証で確定する。

利用者が SCR-03 を閉じた場合、同じページのままでは再表示せず、次の対象となる読み込み・再読み込み・URL が変わるページ内遷移で再判定する。タスクと画像の削除は確認後にまとめて確定し、キャンセル時は削除しない。

## 3. 機能構成

| 機能             | 担当コンテキスト                  | 概要                                                                                       | 対応 FR        |
| ---------------- | --------------------------------- | ------------------------------------------------------------------------------------------ | -------------- |
| 登録画面起動     | background、拡張機能画面          | コマンドから起動元タブを特定し、独立ウィンドウで登録画面を開く                             | FR-002         |
| 撮影             | background、content、拡張機能画面 | 表示範囲またはページ全体を撮影し、登録画面に結果を渡す                                     | FR-002、FR-003 |
| タスク管理       | 拡張機能画面、background          | 一覧、編集、完了、削除を扱う                                                               | FR-002、FR-003 |
| 対象ドメイン判定 | background                        | URL のホストを正規化し、PSL を使って比較対象を求める。localhost・IP はホスト完全一致とする | FR-003、FR-004 |
| リマインド判定   | background                        | ナビゲーションに応じ、完了状態と停止期間を考慮して対象を判定する                           | FR-004         |
| リマインド表示   | background、拡張機能画面          | 独立ウィンドウに表示・更新する                                                             | FR-004         |
| 停止期間管理     | 拡張機能画面、background          | タスクまたは対象ドメインごとに終了日時を保存・変更・解除する                               | FR-004         |

ページ内遷移は `webNavigation` の History API 更新とフラグメント更新を検知する案とし（REF-013）、URL が変わらない画面切り替えは対象外とする。再読み込みは URL が変わらなくても対象とする。Service Worker の停止・再起動を前提とし、永続状態をグローバル変数だけに保持しない（REF-014）。

撮影元をタブ ID で指定できる `tabCapture.getMediaStreamId` を採用候補とし、対象タブで利用者が拡張機能を操作して `activeTab` が付与された後に、映像のみを取得する案とする（REF-064）。映像の取得・画像化は独立した拡張機能画面で行い、音声は取得しない。取得に失敗した場合は理由を表示し、入力を保持する。一覧から既存タスクの画像を追加する場合は、そのタスクの URL を新しいタブで開いて利用者がアイコンを操作する。映像の取得によって popup が閉じる場合があるため、編集時は独立画面を使用する案とする（REF-065）。

従来案の `tabs.captureVisibleTab` は呼び出し時にアクティブなタブを撮影し、撮影結果にタブ ID を含まない（REF-011）。撮影の前後で同じタブがアクティブでも、その間に別タブへ切り替えて戻した場合に、前後確認だけでは撮影元を証明できない。`tabCapture` 案には新たな権限が必要であり、利用者操作による権限付与、対象タブを切り替えた場合の結果、画面終了・ページ遷移時の停止と復旧は未検証である。対象・文書・画像の一致を確認できなければ成功扱いにしない。

表示範囲は一度に撮影する。ページ全体の撮影は FR-002 に従い、撮影開始時点で読み込み済みの範囲を対象とし、スクロールにより新たに読み込まれる内容は対象外とする。開始時の範囲とスクロール位置を記録し、自動スクロールして撮影した画像を結合する案とする。成功時・失敗時のいずれも元のスクロール位置と表示状態の復元を試み、復元できない場合は通知する。対象範囲を正しく撮影できない場合や、撮影中にタブが切り替わる、ページが変わる、画面サイズが変わる場合は撮影を中止して理由を表示し、入力を保持する。固定要素・動的コンテンツを含むページで開始時点の内容を判別・撮影できるかは未検証であり、正しく撮影できない場合は成功扱いにしない。撮影結果が5,000,000バイトを超える場合は保存せず、上限超過を表示する。

## 4. コンテキスト間メッセージ

以下は論理的なメッセージ案であり、具体的な型・認可方法は詳細設計で定める。Chrome のメッセージは JSON シリアライズ可能なデータを扱う（REF-019）。

| メッセージ名                         | 送信元 → 送信先           | ペイロード                           | 応答                       |
| ------------------------------------ | ------------------------- | ------------------------------------ | -------------------------- |
| OPEN_REGISTRATION                    | background → 拡張機能画面 | 起動対象のタブ・ウィンドウの識別情報 | 起動結果またはエラー       |
| NAVIGATION_CHANGED                   | background → 拡張機能画面 | 対象ドキュメントの識別情報           | 表示処理の結果またはエラー |
| TASK_QUERY / TASK_SAVE / TASK_DELETE | 拡張機能画面 → background | 検索条件、タスクまたはタスク ID      | 結果またはエラー           |
| SUPPRESSION_UPDATE                   | 拡張機能画面 → background | 対象と終了日時、または解除要求       | 結果またはエラー           |
| CAPTURE_REQUEST / CAPTURE_RESULT     | 拡張機能画面 ↔ background | 撮影対象の識別情報・範囲、画像結果   | 結果またはエラー           |
| CAPTURE_SCROLL                       | background ↔ content      | 撮影のためのスクロール指示・位置情報 | 操作結果またはエラー       |

タスク内容・画像を content、ページと共有する DOM、`window.postMessage` に渡さない。独立画面と background 間の送信元を検証し、ページからの要求ではタスク情報を返さない。元タブとリマインド画面の識別情報は `chrome.storage.session` に保存し、Service Worker の再起動後に読み直す案とする（REF-020）。復元時はタブと画面の存在を確認し、無効な対応を破棄する。ブラウザ再起動や拡張機能の更新等でセッションデータは消去されるため、以前の識別情報を別のタブに再利用しない。対応を確認できないリマインド画面は内容を表示せず閉じる。画像の転送方法、対応付けの作成・画面起動の競合防止と復元処理の実現性は未検証である。

| `webNavigation`                                        | ページ読み込み・History API・フラグメントの変化を検知する    | FR-004                 | content だけの監視では検知範囲とページの影響を確認する必要がある（REF-013）                                                  |
| `unlimitedStorage`                                     | IndexedDB の容量制限・退避の影響を抑え、100MB の保持を目指す | FR-002、FR-003、FR-004 | 権限なしでは容量制限や退避があり得る（REF-014）                                                                              |
| `storage`                                              | リマインド画面と元タブの対応をブラウザセッション中に保持する | FR-004                 | Service Worker のグローバル変数だけでは停止時に失われる（REF-020）                                                           |
| `host_permissions`: `http://*/*`, `https://*/*`        | 通常の HTTP・HTTPS タブの URL 等を扱う                       | FR-002、FR-004         | `activeTab` のみではユーザー操作なしの再訪時検知に必要なアクセスを賄えない可能性がある。必要性を検証する（REF-011、REF-012） |
| `content_scripts.matches`: `http://*/*`, `https://*/*` | 全体撮影時のページ操作に備え content を起動する              | FR-002、FR-003         | 必要時のみ注入する方法も比較し、必要な権限を確認する（REF-009）                                                              |

`commands` は manifest の宣言であり、上記の permission とは別に必要となる（REF-022）。画面をページに埋め込まないため、画面を `web_accessible_resources` として公開しない。撮影時の `activeTab` はコマンド実行で付与されるが、遷移等で失効し得る（REF-012）。権限がないときは失敗を表示し、入力を保持する。

既存タスクの撮影用に開く新しいタブには、撮影元のタブで付与された一時権限を引き継ぐ前提を置かず、対象タブでの拡張機能アイコンの操作により `activeTab` を付与する（REF-012）。この手順と popup を介した撮影は実機で確認する。REF-011 の一般説明では一致するホスト権限でも撮影可能と記載される一方、`captureVisibleTab` の個別説明は `<all_urls>` または `activeTab` を必要としているため、HTTP・HTTPS のホスト権限だけを撮影権限の根拠にしない。

## 6. 保存データ

タスク・画像等は拡張機能オリジンの IndexedDB に、画面とタブの対応は `chrome.storage.session` に保存する案とする（REF-014、REF-020、ADR-0003）。保存先は端末内のみで、同期ストレージは使用しない。キー・型は論理的な案であり、スキーマの詳細は後続工程で定める。

| キー                  | 型                                                                                         | 保存先              | 保持期間                                             | 個人情報                                |
| --------------------- | ------------------------------------------------------------------------------------------ | ------------------- | ---------------------------------------------------- | --------------------------------------- |
| `tasks`               | タスク ID、URL、ホスト、タスク名、期限、詳細、完了状態、登録日時、タスク単位の停止終了日時 | IndexedDB（端末内） | 削除または拡張機能アンインストールまで               | 入力内容・URL に含まれる可能性あり      |
| `images`              | 画像 ID、タスク ID、画像 Blob                                                              | IndexedDB（端末内） | 画像・タスクの削除または拡張機能アンインストールまで | 画像に含まれる可能性あり                |
| `domain_suppressions` | 停止対象を再計算する基準ホスト、停止終了日時                                               | IndexedDB（端末内） | 解除または拡張機能アンインストールまで               | 基準ホストに含まれる可能性あり          |
| `edit_drafts`         | 撮影前に一時保存した編集内容・画像と対象タスクの識別情報                                   | IndexedDB（端末内） | 編集の保存・取消または拡張機能アンインストールまで   | 入力内容・URL・画像に含まれる可能性あり |
| `reminder_windows`    | 元タブとリマインド画面の識別情報                                                           | storage.session     | 対応の解除またはブラウザ再起動・拡張機能更新等まで   | タスク内容・画像は含めない              |

タスクと画像の追加・変更・削除は整合性を保つようトランザクションで扱う。撮影前の一時保存では登録済みタスクを変更せず、編集の保存時に変更を確定する。容量不足・保存エラーは変更を確定せず理由を通知し、入力を保持する。合計100,000,000バイトを超えても空き容量があれば保存を許可する。

NFR-AVL-001 の検証では、タスクデータを UTF-8 で表現したバイト数と画像のバイト数の合計を計算し、IndexedDB の内部管理領域は含めない。画像の枚数・サイズ上限を守り、合計100,000,000バイトのタスクデータと画像を保存して再表示できることを確認する。一時データや IndexedDB の内部管理領域にも別途空き容量が必要となる。タスクデータの具体的な表現形式と検証データの作成方法は未決である。

PSL 判定には `tldts` を候補とし、拡張機能の更新時に判定情報を更新する。`example.co.jp` と `other.co.jp`、`user-a.github.io` と `user-b.github.io` を区別するため、共有サービスを含むルールを使用する（REF-015、REF-016、REF-023）。タスクは現在の判定情報で再判定する。ドメイン単位の停止は、リマインド画面から設定する場合は対象ページのホスト、一覧から設定する場合は選択した対象ドメインのホストを基準として記録し、現在の判定情報で停止対象を再計算する。

`localhost`・IP アドレス、およびライブラリで登録可能なドメインを取得できないホストは、正規化後のホストが完全一致する場合のみ同じ対象とする。

判定情報の更新により複数のドメイン停止設定が同じ対象に該当する場合は、最も遅い終了日時まで停止する。個々の設定を保持し、現在の判定情報に基づいて判定する。対象ドメインの停止期間を変更すると、現在の判定で該当する設定すべての終了日時を変更する。解除すると、それらの設定をすべて削除する。

## 7. 外部インターフェース

- Chrome の commands、tabs、webNavigation、windows、runtime の各 API、および IndexedDB を利用する案とする。
- タスクデータ・画像の外部送信やネットワーク同期は行わない。
- Vue 3 と PSL 判定用データ・ライブラリは同梱する案とし、実行時にリモートコードを取得しない。`tldts` の採用版を固定し、更新時に PSL も更新する。採用前に同梱物と配布条件を含むライセンスを確認する。具体的なバージョンとライセンスの確認は未了。

## 8. 非機能要件への対応

| NFR ID       | 対応方針                                                                                                   |
| ------------ | ---------------------------------------------------------------------------------------------------------- |
| NFR-PERF-001 | ページ読み込み完了時またはページ内遷移時から3秒以内に独立画面を表示する。測定条件と実現性は未検証          |
| NFR-AVL-001  | IndexedDB と `unlimitedStorage` を用い、タスクと画像の合計100MBの保存・再表示を検証する                    |
| NFR-AVL-002  | タスクと画像を端末内に永続化し、Chrome 再起動後の再表示を確認する                                          |
| NFR-SEC-001  | タスクデータ・画像を外部送信せず、独立した拡張機能画面で扱う。ページへ露出しないことと送信元の検証は未検証 |
| NFR-CMP-001  | Windows の確認時点の Google Chrome 最新版で FR-002〜FR-004 を検証する                                      |

性能の検証条件案として、Windows の検証端末で、対象ドメインに未完了タスク100件、別ドメインに未完了タスク100件を登録し、画像は付けない。HTTP と HTTPS のそれぞれについて、新規読み込み・再読み込み・History API による URL 変更・フラグメント変更を各10回測定し、計80回すべてで対象タスクが表示されるまで3秒以内であることを確認する。開始点はページ読み込み完了または URL の変化、終了点はリマインド画面への対象タスクの描画とする。Chrome のトレースを使用し、開始・終了を同じ時間基準で記録する案とする（REF-026）。端末の CPU・メモリ・Windows と Chrome のバージョンを記録し、検証実施時に Chrome が最新版であることを確認する。この条件は検証の一例であり、要件の対象をこの条件に限定しない。開始・終了点の取得方法、時間基準の一致および3秒以内の実現性は未検証である。

NFR-SEC-001 の確認にはテスト用タスクと画像を使用し、拡張機能のネットワーク通信と、テスト用ページの DOM・ページへのメッセージを観測する。各操作でタスクデータ・画像がページに露出せず、外部に送信されないことを確認する。観測方法の網羅性は未検証である。

ドメイン判定はサブドメイン、共有サービス、IP、登録可能なドメインを取得できないホストと、PSL 更新後の停止設定を検証する。

## 10. 未決事項

### 詳細設計で検討する事項

- 画面と元のタブの対応付けにおける作成・画面起動の競合防止と復元処理、画像の転送方法。
- `tabCapture` 権限の追加と、映像取得の独立画面・利用者操作・編集再開の詳細。
- `tldts` のバージョン・同梱データのライセンス確認。
- タスクデータのバイト数を測定する具体的な表現形式、100MB の検証データの作成方法。
- 情報露出・外部送信の観測方法、性能測定の開始・終了点の取得方法。

ADR に残る設計上の未決事項も詳細設計で検討する。ただしライセンスと配布条件の確認は、ライブラリの採用・導入前に行う。

### 後工程での検証

- 画面と元のタブの対応付けと復元、ページへの情報露出防止と外部送信の観測。
- ページ全体の撮影・復元、固定要素・動的コンテンツの扱い、popup を介した新しいタブの撮影手順の実機確認。
- 100MB の保存・再表示、性能測定の時間基準の一致と3秒以内の実現性。

これらの検証条件をテスト設計で定め、実装後に確認する。不合格または検証不能の場合は成功扱いにせず、必要な設計を見直して再承認を受ける。
