# DD-capture-001 ページのスクリーンショット取得

## 1. 概要

BD-001、FR-002、FR-003、NFR-SEC-001 に対応し、通常の HTTP・HTTPS ページの表示範囲、または撮影開始時点で読み込み済みのページ範囲を撮影する。結果はタスク登録・編集画面で画像として扱う。画像の永続化とタスク管理の画面操作は対象外とする。

ページ全体について、開始時に読み込み済みだった内容を漏れなく識別し、撮影時に変化していないことを確認する手段は未確定である。確認できない場合を成功扱いにしない。

## 2. モジュール構成

| ファイル                               | 役割                                                     |
| -------------------------------------- | -------------------------------------------------------- |
| `src/background/capture-controller.ts` | 撮影元の確認、撮影の実行・中断                           |
| `src/content/capture-page.ts`          | 撮影に必要なページの位置・サイズの取得とスクロール       |
| `src/shared/capture-types.ts`          | 撮影要求・結果・エラーの型                               |
| 独立した拡張機能画面                   | ストリーム取得・画像化、範囲選択、結果確認と失敗時の表示 |

上記は実装予定の論理構成であり、ファイルはまだ作成しない。

## 3. インターフェース

```ts
type CaptureScope = "visible" | "loaded-page";

interface CaptureTarget {
  tabId: number;
  windowId: number;
  documentId: string;
  url: string;
}

interface CaptureRequest {
  requestId: string;
  target: CaptureTarget;
  scope: CaptureScope;
  owner: { kind: "registration" | "edit"; id: string };
}

type CaptureErrorCode =
  | "PERMISSION_DENIED"
  | "TARGET_CHANGED"
  | "VIEWPORT_CHANGED"
  | "UNSUPPORTED_PAGE"
  | "CAPTURE_FAILED"
  | "IMAGE_TOO_LARGE"
  | "RESTORE_FAILED";

type CaptureResult =
  | { ok: true; requestId: string; imageId: string; byteLength: number }
  | {
      ok: false;
      requestId: string;
      code: CaptureErrorCode;
      restorationFailed: boolean;
    };
```

- 要求元と対象タブの対応、利用者の操作、および対象の URL・ドキュメントを確認する。
- `requestId` は撮影操作、一時結果のキーを表し、成功結果の `imageId` は画像を指す識別子とする。画面は所有者を確認したうえで拡張機能オリジンの IndexedDB から `requestId` を使って画像を取得する（REF-014）。Chrome メッセージには識別子と結果だけを含め、画像本体を content script やページに渡さない。
- 既存タスクの撮影用タブでは、編集内容の一時保存後に新しいタブを開き、そのタブで拡張機能アイコンを操作して `activeTab` を付与する案とする（REF-012）。
- メッセージは JSON 化可能な値のみを使用する（REF-019）。画面からの要求は、送信元の拡張機能 ID・オリジン・許可された画面 URL・画面と撮影操作の対応を確認し、確認できない場合は拒否する。送信元の `tab` や `documentId` は常に存在するとは限らず、popup と独立画面それぞれの確認方法は未決（REF-031）。

## 4. 処理詳細

1. 要求元を認証し、対象タブ・ウィンドウ・ドキュメント・URL が要求時と一致し、対象タブがそのウィンドウでアクティブであることと、必要な撮影権限を確認する。確認できない場合は撮影せず理由を表示する。
2. 独立した拡張機能画面で `tabCapture.getMediaStreamId({ targetTabId })` を呼び出し、同じ画面で `getUserMedia` にストリーム ID を渡して映像のみを取得する案とする（REF-064、REF-065）。ID は一度しか使用できず数秒で失効するため、直ちに使用し、保存・再利用・ログ出力をしない。`targetTabId` と利用者操作による `activeTab` が必要である。取得失敗または対象の確認不能時は中止して理由を表示する。画面起動後も対象タブの権限が有効か、独立画面で取得できるかは実機で検証する。
3. 映像のフレームを画像化し、表示範囲の結果とする案とする。読み込み済みページ範囲では、開始時のページ範囲、表示サイズ、スクロール位置と復元に必要な状態を記録し、自動スクロールとフレーム取得を繰り返して画像を結合する案とする。スクロール後の正しい位置・対象文書に対応するフレームを識別できることは未検証であり、確認できなければ成功扱いにしない。
4. 各撮影前後に対象・画面サイズの整合性を確認する。タブ切替、ページ変更、サイズ変更、権限失効または撮影失敗を検知した場合は中止する。途中画像を成功結果として返さない。
5. 成功・失敗・中止時に元のスクロール位置と変更した表示状態の復元を試みる。復元失敗は撮影結果とは別に通知する。元のドキュメントがなくなった場合に復元できるとは限らない。
6. 結合後の画像が5,000,000バイトを超える場合は登録せず、上限超過を表示する。変更後の画像が10枚を超える追加は行わない。既存の１枚を差し替える場合は変更後の枚数で判定する。撮影・登録に失敗しても入力を保持する。

取得したストリームの映像トラックは成功・失敗・取消のいずれでも停止する。画面終了・タブ終了・ページ遷移・トラック停止を検知した場合は撮影を中止し、復元可能な状態を確認する。ストリームはタブ内の遷移をまたいで継続するため、ストリームが生存していることだけを同じ文書である証拠にしない（REF-064）。Worker や画面の停止とイベント通知の競合を含む検知方法は未確定。

### 4.1 画像の一時保持と編集画面の再開

既存タスクの編集では、編集内容の一時保存後に対象 URL の新規タブを開き、そのタブ ID と編集一時データの ID を `chrome.storage.session` に対応付ける案とする（REF-020）。対象タブでアイコンが操作されたとき、拡張機能 popup は対応を照合し、撮影用の独立画面を開く案とする。独立画面で撮影範囲を選択し、撮影後に一時保存した編集内容と結果を再開する。対応しないタブでアイコンが操作された場合は通常の一覧を表示し、別の編集操作と関連付けない。新規タブの作成・対応付けに失敗した場合は撮影に進まず、編集内容を保持し、画面が開いていれば理由を表示する。タブ閉鎖や拡張機能再起動で対応が失われた場合は、一時保存済みの編集を利用者が再開できるようにする。独立画面の起動と編集再開の具体的な操作、画面が閉じた場合の通知方法と session の競合制御は未決。

popup が設定されたタブでは `action.onClicked` は発火しないため、アイコン操作時に同イベントで対応付ける前提は置かない（REF-035）。popup が取得できる対象タブ情報と `activeTab` の付与は実機で確認する。

1. 拡張機能オリジンの IndexedDB に、撮影操作の ID、所有者、状態と撮影結果を保持する一時ストアを置く。画像を保存する場合は `Blob` として保持し、ページ由来の保存領域には書き込まない（REF-014）。
2. 撮影開始前に状態 `pending` を保存する。編集時は編集内容の一時保存も成功していることを確認する。どちらかの保存に失敗した場合は撮影せず、画面に理由を表示する。
3. 撮影と復元が成功し、画像サイズが上限内の場合に限り、所有者に対応する一時結果を `ready` として保存し、画面に識別子を通知する。失敗時は画像を保存せず、エラー種別を一時結果に記録する。
4. 編集 popup が閉じても一時結果と編集内容は保持し、再度開いたときに所有者を照合して結果またはエラーを表示する。状態の記録に失敗した場合を含め、`pending` のまま再開した場合は成功扱いにせず、未完了であることを表示する。
5. 編集画面で画像の追加を確定するときは、一時結果から編集途中の画像一覧への移行と一時結果の削除を同一トランザクションで行う。登録画面では画像を画面側で受け取り、受け取りを確認してから一時結果を削除する。保存・取消時の一時結果の残存や、画面・Service Worker の停止中に中断した操作の復旧・整理手順は未決。

固定要素、スクロール中に遅延読み込みされる内容、アニメーション、動画、キャンバス、iframe などで開始時点の表示内容が変化する場合がある。対象範囲の正確な識別と変化の検知・固定要素の結合方法は未決であり、実機で検証する。対象範囲を正しく撮影できない場合は失敗を表示する。

### 4.2 中断・取消と撮影結果の競合案

1. 撮影要求 ID は再利用しない。撮影結果の書き込み時は、一時ストアに同じ要求 ID と所有者の `pending` が残っていることを同一 `readwrite` トランザクションで確認する。存在しない、所有者が異なる、または `pending` 以外なら画像を書き込まず、遅れて届いた結果を追加しない。
2. 編集の取消・保存時に対応する一時結果を整理する場合、編集一時データと撮影結果の更新・削除を同一トランザクションで行う案とする。登録画面の取消でも、対応する要求を無効にして遅れた結果を受け取らない。進行中の撮影に対しては中止・復元を要求するが、その完了を確認する前に「復元成功」と表示しない。
3. 画面や Service Worker が途中で停止し、撮影や復元の成否が確認できない場合は `pending` のままとし、撮影完了や復元成功と表示しない。経過時間だけを根拠に成功・失敗を決定せず、入力と受取済みの画像を保持する。利用者が未完了の要求を破棄して再試行できる操作を設ける案とする。無効化後も復元状態を確認できなければ、その旨を表示する。
4. `ready` の画像は追加・差し替えの確定、明示的な破棄、または所有する登録・編集の取消まで残す。画像移行の失敗時は一時結果を保持する。要求の無効化・復元完了の通知と、画面が閉じている間の通知方法は未決。

IndexedDB と Chrome API の操作は一つのトランザクションにはできないため、要求の無効化だけでページ状態の復元を保証しない（REF-030）。タブやドキュメントが消えた場合を含めて復元不能を通知する方法を検証する。

### 4.3 ページ全体撮影の確認範囲

開始時の読み込み済み範囲と、その後の内容変化をすべての Web ページで確実に識別できるとは限らない。固定要素の重複、遅延読み込み、canvas・動画、クロスオリジン iframe などを含むページを対象に、内容の識別・結合・復元を別々に検証する。識別・検証できない場合は画像を成功結果として追加しない。静的ページでも正確性の検証が成功するまでは、撮影できると保証しない。

#### 仕様確認結果

- `captureVisibleTab` はウィンドウ内で呼び出し時にアクティブなタブを撮影し、結果は画像データであり撮影元のタブ ID を含まない（REF-011）。前後のタブ確認が一致しても、その間に別のタブへ切り替えて戻した場合に、画像が対象タブ由来であるとこの確認だけでは証明できない。対象切替の監視と API 実行の競合を含む対策は未確定。
- `MutationObserver` は DOM ツリーの変更を監視する API であり、それだけで動画・canvas の画素の変化を網羅できる根拠にはならない（REF-050）。別オリジンの iframe の内部は同一オリジンポリシーにより直接調べられない場合がある（REF-051）。DOM の監視だけで全ページの撮影範囲・内容を保証しない。
- アイコン操作は `activeTab` の付与契機であり、popup のあるタブで `action.onClicked` は発火しない（REF-012、REF-035）。これは仕様上の確認であり、撮影用タブからの popup 再開や権限の実動作を確認した結果ではない。

後工程では、自動スクロール中のタブ切替と切戻し、DOM を変更しない画素更新、別オリジン iframe、撮影の途中停止を検証する。画像の正確性や復元可否が確認できない場合は成功扱いにしない（BD-001）。

## 5. 状態遷移

| 状態       | 契機                             | 次の状態   |
| ---------- | -------------------------------- | ---------- |
| 待機       | 利用者が撮影を要求               | 対象確認中 |
| 対象確認中 | 対象・権限を確認                 | 撮影中     |
| 撮影中     | 対象範囲の取得完了               | 復元中     |
| 撮影中     | 中断条件・エラー                 | 復元中     |
| 復元中     | 撮影・復元が成功し、画像が上限内 | 結果確認   |
| 復元中     | 撮影・復元または上限確認に失敗   | エラー表示 |
| 結果確認   | 利用者が画像を追加               | 待機       |

復元に失敗した場合は撮影自体を失敗とし、取得済み画像を追加せず、復元できなかった理由を表示する。撮影自体も失敗していた場合は撮影と復元の両方の失敗を通知する。

## 6. エラー処理

| エラー                       | 検知方法                       | ユーザーへの表示             | ログ           |
| ---------------------------- | ------------------------------ | ---------------------------- | -------------- |
| 権限なし                     | 権限確認または API の失敗      | 対象タブでの操作が必要と表示 | エラー種別のみ |
| タブ・ページ変更             | タブ・ドキュメント・URL の照合 | 撮影を中止した理由を表示     | エラー種別のみ |
| サイズ変更                   | 記録した表示サイズとの照合     | 撮影を中止した理由を表示     | エラー種別のみ |
| 対象範囲を正しく撮影できない | 対象範囲・内容の検証           | 撮影できなかった理由を表示   | エラー種別のみ |
| 撮影・結合失敗               | API または画像処理の失敗       | 撮影できなかったことを表示   | エラー種別のみ |
| 画像上限超過                 | 件数・バイト数の確認           | 超過した上限を表示           | エラー種別のみ |
| 表示状態の復元失敗           | 復元処理の失敗                 | 復元できなかったことを表示   | エラー種別のみ |

いずれの場合も成功扱いにせず、入力内容を保持する。利用者が既に閉じた画面への通知方法は未決。

## 7. ログ出力

エラー種別のみを記録し、URL・ホスト・タスク内容・画像を出力しない。content script にはスクロールなど撮影に必要な情報だけを渡す。

## 8. テスト観点

- 正常系: 表示範囲の撮影、静的ページの全体撮影、スクロール位置の復元、編集途中の撮影と入力再開。
- 異常系: 権限失効、タブ切替、ページ遷移、画面サイズ変更、撮影途中の失敗、復元失敗。
- 異常系: popup の終了・再開、撮影結果の保存失敗、結果移行途中の失敗、所有者が一致しない要求。
- 異常系: 要求の取消・破棄と撮影完了が競合しても、遅れた結果が画像として追加されないこと。Service Worker 停止中の復元不能を成功扱いにしないこと。
- 異常系: 動的コンテンツ・固定要素・iframe を含むページで正確な撮影を確認できない場合の失敗通知。
- 境界値: 画像10枚・11枚、5,000,000バイト・5,000,001バイト、ストリーム ID の期限切れ・再使用。
- 実機: 利用者操作後の権限付与、独立画面での対象タブ指定・映像のみの取得、タブ切替・ページ遷移・画面終了時の中断とトラック停止。
- セキュリティ: 画像とタスク内容がページ・content script に渡らず、拡張機能から外部送信されないこと。

## 9. 未決事項

- 開始時に読み込み済みの範囲の識別、撮影中の変化検知、固定要素・動的コンテンツ・iframe の扱いと正確性の検証方法。
- 対象タブ・文書・フレームの対応付けと変更検知の競合、タブと編集一時データの対応付け・解除と session の競合制御、権限付与・独立画面での取得と編集再開の実機確認。
- 一時結果の所有者の認証、画面・Service Worker 停止時の復旧・整理、関連する詳細設計との整合。
- 要求画面が閉じた場合の通知方法。
- Chrome メッセージの詳細な型と、popup・独立画面それぞれの送信元確認方法。
