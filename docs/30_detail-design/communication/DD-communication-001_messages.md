# DD-communication-001 拡張機能内のメッセージと送信元確認

## 1. 概要

BD-001、FR-002、FR-003、FR-004、NFR-SEC-001 に対応し、拡張機能画面・Service Worker・content script 間のメッセージ形式と送信元確認の案を定める。撮影、タスク保存、リマインドの個別処理は対象外とする。

本書は案であり、popup と独立画面で取得できる送信元情報、画面との対応付け、および関連する詳細設計との整合は未確認。

## 2. モジュール構成

| ファイル                           | 役割                                        |
| ---------------------------------- | ------------------------------------------- |
| `src/shared/messages.ts`           | メッセージの種類・要求 ID・応答・エラーの型 |
| `src/background/message-router.ts` | 種類と送信元の検証、処理への振り分け        |
| 拡張機能画面                       | 操作要求の送信と応答の表示                  |
| `src/content/`                     | 撮影に必要なページ操作と、その結果の送信    |

上記は実装予定の論理構成であり、ファイルはまだ作成しない。

## 3. インターフェース

Chrome メッセージには JSON 化可能な値を使用する。型は内部の論理案であり、各操作のペイロードは確定していない（REF-019）。

```ts
type MessageKind =
  | "OPEN_REGISTRATION"
  | "TASK_QUERY"
  | "TASK_SAVE"
  | "TASK_DELETE"
  | "SUPPRESSION_UPDATE"
  | "CAPTURE_REQUEST"
  | "CAPTURE_RESULT"
  | "CAPTURE_SCROLL"
  | "NAVIGATION_CHANGED";

type JsonValue =
  | null
  | boolean
  | number
  | string
  | JsonValue[]
  | { [key: string]: JsonValue };

interface MessageRequest {
  version: 1;
  requestId: string;
  kind: MessageKind;
  payload: JsonValue;
}

type MessageResponse =
  | { requestId: string; ok: true; payload: JsonValue }
  | { requestId: string; ok: false; code: string };
```

`requestId` は要求と応答を対応付ける一意な識別子とし、それ自体を送信元の認証情報として扱わない。画像の `Blob` はメッセージに含めない。タスク・画像の保存内容はページや content script に送らない。

| 種類                                       | 許可する方向                            | 内容                                                     |
| ------------------------------------------ | --------------------------------------- | -------------------------------------------------------- |
| `OPEN_REGISTRATION`                        | Service Worker → 登録画面               | 起動した操作と対象の対応を確認する識別情報               |
| `TASK_QUERY` / `TASK_SAVE` / `TASK_DELETE` | 登録・一覧画面 → Service Worker         | 対象、検索条件、保存要求、または削除要求                 |
| `SUPPRESSION_UPDATE`                       | 一覧・リマインド画面 → Service Worker   | 停止対象、終了日時または解除                             |
| `CAPTURE_REQUEST`                          | 登録・撮影用独立画面 → Service Worker   | 撮影対象・範囲・操作の識別情報                           |
| `CAPTURE_RESULT`                           | Service Worker → 要求元画面             | 撮影操作の識別情報、結果またはエラー。画像本体は含めない |
| `CAPTURE_SCROLL`                           | Service Worker ↔ 対象の content script  | スクロール指示、対象文書と必要な位置・サイズ、結果       |
| `NAVIGATION_CHANGED`                       | Service Worker → 対応するリマインド画面 | 更新対象の識別情報                                       |

画像を含む登録・編集内容の保管と参照方法、各種類の具体的なフィールドとエラーコードは関連設計と合わせて確定する。上表は全フィールドの定義ではない。

## 4. 処理詳細

1. 受信側は `version`・`kind`・要求 ID・種類ごとの必須フィールド、型、範囲を検証する。未対応の版や種類、不正な値は処理せずエラーとする。信頼できない入力に基づくパスや ID を無条件に使用しない。
2. 画面からの要求は、`MessageSender` の拡張機能 ID・送信元 URL・オリジンを確認し、拡張機能に属する許可された画面と操作の組み合わせだけを受け付ける。必要な情報が得られない場合は推測せず拒否する。`tab`・`documentId`・`origin` などは常に得られるとは限らない（REF-031）。
3. 画面の種類だけでは対象の登録・編集・リマインド操作の所有者であることは証明できない。対象タブ・文書・画面との対応を、Service Worker が管理する情報と照合する。照合方法が確立するまでは、機密情報の要求を許可する前提にしない。
4. content script との通信では対象タブ・フレーム・文書を照合し、撮影に必要な情報だけを扱う。ページと共有する DOM や `window.postMessage` を経由してタスク内容・画像を渡さない（REF-009、REF-010）。
5. 応答は要求 ID に対応させ、失敗時はエラーコードを返す。応答が届かない場合、操作が未実行だったとは限らないため、要求を無条件に再送しない。保存済み状態や操作 ID を照合する方法は未決。
6. 同じ要求を複数の受信処理が同時に応答しないように振り分ける。非同期応答には `sendResponse` とリスナーの `return true` を使う案とする（REF-019）。通信断・Service Worker 停止時は失敗または結果不明として利用者に通知し、成功扱いにしない。

### 4.1 仕様確認結果

- `MessageSender` の `id`・`url`・`origin`・`documentId`・`tab` は省略可能であり、`tab` はタブからの接続の場合に限られる（REF-031）。これらがどの画面で得られるかは実機で確認する。存在しないフィールドを常に要求すると正当な画面の要求も拒否し得る。
- `runtime.getContexts()` は Chrome 114 以降の拡張機能コンテキストを取得できる。文書の ID・URL・オリジンは省略可能で、タブやウィンドウに属さない場合の ID は `-1` である（REF-031）。API のフィールドが存在することだけでは、特定の撮影・登録操作の所有者であることを証明できない。
- 公式仕様は非同期応答で `return true` を利用する方法を示している（REF-019）。接続断と保存処理の確定結果は別に確認する必要がある。再試行の判定に使う操作記録と保存を同一トランザクションにまとめる案は、対象操作と保持期間が未確定。
- 同じ拡張機能オリジンの画面からは IndexedDB にアクセスできるため、Service Worker のメッセージ検証だけを画面ごとの保存データへのアクセス制御とみなさない（REF-014、REF-051）。各画面の信頼境界と一時データの読み取り方法は未決。

## 5. 状態遷移

| 状態     | 契機               | 次の状態         |
| -------- | ------------------ | ---------------- |
| 未送信   | 要求を送信         | 応答待ち         |
| 応答待ち | 対応する成功応答   | 完了             |
| 応答待ち | 対応するエラー応答 | エラー表示       |
| 応答待ち | 通信断・応答未取得 | 結果不明         |
| 結果不明 | 保存状態を確認     | 状態に応じて復旧 |

結果不明からの個別操作の復旧・再試行手順は未決。

## 6. エラー処理

| エラー                 | 検知方法                        | ユーザーへの表示             | ログ           |
| ---------------------- | ------------------------------- | ---------------------------- | -------------- |
| 不正な要求・未対応の版 | 受信時の型・値の検証            | 操作できなかったことを表示   | エラー種別のみ |
| 送信元・操作の不一致   | 送信元と対応情報の照合          | 操作できなかったことを表示   | エラー種別のみ |
| 操作の失敗             | 処理からのエラー応答            | 対象操作と理由を表示         | エラー種別のみ |
| 通信断・応答未取得     | 通信 API の失敗または応答の欠落 | 結果を確認できないことを表示 | エラー種別のみ |

## 7. ログ出力

エラー種別のみを記録し、メッセージ本文・タスク名・詳細・URL・ホスト・画像・認証用識別情報は出力しない。

## 8. テスト観点

- 正常系: 各画面から許可された操作と要求 ID に対応する応答。
- 異常系: 不正な型・未対応の版、送信元情報の欠落、画面と操作の不一致、通信断と Service Worker 停止。
- 異常系: 保存成功後に応答だけが失われても、再送により重複登録や意図しない削除をしないこと。
- セキュリティ: content script やページから機密情報を取得できず、画像本体がメッセージに含まれないこと。
