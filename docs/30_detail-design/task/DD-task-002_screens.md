# DD-task-002 タスク登録・一覧・編集画面

## 1. 概要

BD-001、FR-002、FR-003、FR-004 に対応し、登録画面 SCR-01 と、一覧・編集画面 SCR-02 の入力、表示および操作を定める。リマインド画面 SCR-03、撮影と保存の内部処理は対象外とする。

本書の画面構成と操作は案であり、撮影・保存・リマインドの詳細設計との整合と実現性は未確認である。

## 2. モジュール構成

| ファイル            | 役割                                                 |
| ------------------- | ---------------------------------------------------- |
| `src/registration/` | 独立した登録画面、入力と撮影結果の表示               |
| `src/popup/`        | 一覧、絞り込み、編集、削除確認と停止期間の設定       |
| `src/shared/`       | 画面に共通する入力検証、一覧の並び替えと表示用の判定 |

上記は実装予定の論理構成であり、ファイルはまだ作成しない。タスク内容や画像は拡張機能画面内で扱い、閲覧ページや content script に表示・送信しない（REF-009、REF-010）。

Vue の候補 3.5.46 は MIT と表記され、パッケージにライセンスファイルと複数の依存先がある（REF-027、REF-044）。実際に同梱する依存先、版、配布条件と保守状況は採用・導入前に確認する。パッケージの表記だけで確認完了とはしない。

候補版の直接依存先は `@vue/shared`、`@vue/runtime-dom`、`@vue/compiler-dom`、`@vue/compiler-sfc`、`@vue/server-renderer` の 3.5.46 と指定される（REF-027）。これは直接依存の一覧であり、ビルド時・間接依存や成果物への実際の同梱を確認したものではない。MIT のライセンスファイルに記載された著作権表示と許諾表示の保持条件も、成果物に含まれる部分ごとに確認する（REF-044）。

## 3. インターフェース

画面間と保存処理の実際の通信形式ではなく、画面が扱う情報の論理的な案を示す。画像本体は Chrome メッセージに含めない（REF-019）。

```ts
type CompletionFilter = "all" | "open" | "completed";

type DomainKey =
  | { kind: "domain"; value: string }
  | { kind: "host"; value: string };

interface TaskListFilter {
  completion: CompletionFilter;
  domain: DomainKey | null;
}

interface TaskFormFields {
  name: string;
  url: string;
  dueDate: string | null;
  detail: string;
}

type TaskScreenMode = "list" | "edit" | "delete-confirmation" | "suppression";
```

- ドメインの絞り込みは、BD-001 の対象ドメイン判定によるグループを対象とし、未指定なら全件を表示する。`DomainKey` は現在の判定結果の種別と値を保持し、両方が一致した場合に同じグループとする。リマインド側との型・判定の共通化は未確認。
- 画像一覧は画像の識別情報と表示順を持ち、登録・編集時の確定前に画像の追加・削除・差し替えを反映する。画像本体の受け渡し方法は関連する詳細設計と整合を確認する。
- 入力内容、画像、選択条件は画面ごとに管理し、処理失敗時に消去しない。登録・編集の途中入力は DD-task-001 に従い一時保存し、閉じた後は保存成功を確認できた状態を再開できるようにする。

## 4. 処理詳細

### 4.1 登録画面 SCR-01

1. ショートカットで画面を開いたとき、登録・編集が進行中なら新しい登録を開始せず、進行中であることと完了または破棄が必要なことを表示する。進行中でなければ操作の開始を保存し、起動元の通常の HTTP・HTTPS ページの URL と対象ドメインを表示する。登録画面では起動元の URL とドメインを表示用とし、別のページの情報を代わりに登録しない。
2. タスク名を必須とし、期限・詳細・画像を任意で入力する。期限は日付として扱う。画像の撮影範囲に表示範囲または開始時に読み込み済みのページ範囲を選ぶ。
3. 画像を追加する際は既存画像の件数と取得結果のサイズを確認する。10枚を超える追加や、5,000,000バイトを超える画像は追加せず、上限を表示する。
4. 保存時に必須項目と期限・画像の妥当性を確認する。検証または保存に失敗した場合は対象と理由を表示し、入力と画像を保持する。保存の成功を確認してから画面を閉じる。
5. 取消では登録を確定せず画面を閉じる。撮影中の取消と一時結果の整理方法は未決。

### 4.2 一覧画面 SCR-02

1. アイコンから画面を開き、登録済みタスクを取得する。取得に失敗した場合は失敗を表示し、登録件数が0件であるかのように表示しない。
2. 初期状態では完了・未完了とドメインを絞り込まず表示する。完了状態は全件・未完了・完了から、ドメインは全件または対象ドメインから選択する。両方を指定した場合は両方を満たすタスクを表示する。
3. 期限のあるタスクは期限の近い順、期限が同じ場合は登録日時の古い順とする。期限のないタスクは期限のあるタスクの後に、登録日時の古い順で表示する。期限と登録日時がともに等しい場合は、タスク ID の UTF-16 コード単位の昇順とする案とし、再表示時にも順序を安定させる。
4. 各タスクに名前、対象ドメイン、期限、完了状態を表示する。未完了かつ期限が端末の現地日付より前のタスクは期限超過と表示し、完了済みと期限なしのタスクは期限超過と表示しない。
5. 完了・未完了の変更は保存成功を確認して一覧に反映する。保存に失敗した場合は理由を表示し、成功として扱わない。削除はタスク名と画像も削除される旨を含む確認を表示し、「削除」を選んだときだけ実行する。「キャンセル」では削除しない。
6. タスク単位およびドメイン単位の停止終了日時の設定・変更・解除を選べるようにする。利用端末の現地日時を入力し、設定内容を表示する。入力可能な日付の範囲は未決。

### 4.3 編集画面 SCR-02

1. タスクを選択し、タスク名、URL、期限、詳細および画像を表示する。URL を変更した場合は有効な URL から対象ドメインを再計算し、ドメインだけを編集する操作は設けない。URL が不正な間はエラーを示し、以前のドメインを変更後の URL に対応するものとして表示しない。
2. 画像を追加、個別削除または差し替えできる。差し替えの失敗時は元の画像を保持する。変更はタスクの保存時に確定する。追加・差し替え後の画像は10枚以下、各画像は5,000,000バイト以下とする。
3. 画像の撮影を選んだ場合は、編集途中の内容の一時保存に成功してから対象 URL を新しいタブで開く。利用者がそのタブでアイコンを操作した後、撮影用の独立画面で範囲を選び、撮影後に編集を再開する案とする。一時保存に失敗した場合は撮影に進まず、理由を表示する。独立画面の起動・編集再開の操作と対象の対応付けは DD-capture-001 と合わせて実機確認する。
4. 保存の失敗または別画面による更新との競合を検知した場合は、理由を表示し、入力を保持する。保存または取消が成功した場合は一覧に戻る。撮影用一時データは編集の保存または取消時に削除する。

### 4.4 画面の配置案

各画面は上から次の順で配置し、画面内に収まらない内容はスクロールして操作できるようにする。

| 画面            | 配置                                                                                                                                                                                                                                          |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 登録 SCR-01     | 見出し「タスク登録」→ 起動元の URL・対象ドメイン → タスク名（必須）→ 期限 → 詳細 → 画像一覧・現在の枚数 → 撮影範囲の選択と「撮影」→「保存」「取消」                                                                                           |
| 一覧 SCR-02     | 見出し「タスク一覧」→ 完了状態・対象ドメインの絞り込み → タスク一覧。各行にタスク名・対象ドメイン・期限・完了状態・期限超過表示と、編集・完了状態の変更・削除・タスク停止の操作を置く。ドメイン停止の操作は対象ドメインの選択に関連付けて置く |
| 編集 SCR-02     | 見出し「タスク編集」→ タスク名（必須）→ URL → 自動計算した対象ドメイン → 期限 → 詳細 → 画像一覧・現在の枚数 → 画像ごとの「削除」「差し替え」と「撮影して追加」→「保存」「取消」                                                               |
| 削除確認 SCR-02 | タスク名と「画像も削除されます。」を表示し、「削除」「キャンセル」を置く                                                                                                                                                                      |
| 停止設定 SCR-02 | 操作対象のタスクまたは対象ドメイン → 現在の設定 → 停止終了日時 →「設定・変更」「解除」「キャンセル」を置く                                                                                                                                    |

登録・編集の画像一覧には各画像を区別できる表示を置く。撮影結果の確認では画像と「追加」「破棄」を表示し、差し替えの場合は「追加」を「差し替え」とする。破棄や撮影失敗では元の画像を変更しない。画像が10枚ある場合でも、既存画像の差し替えは変更後の枚数が10枚を超えなければ許可する。

一覧の取得が成功して登録件数が0件の場合は「タスクはありません。」、絞り込み結果だけが0件の場合は「条件に一致するタスクはありません。」と表示する。取得中は「読み込み中」、取得失敗時はエラーを表示し、0件の表示と区別する。

画面寸法の案は、popup を幅360・高さ560 CSS ピクセル、登録画面を幅680・高さ720 CSS ピクセルとし、小さい画面では収まる範囲に縮めて内容をスクロールする。popup は Chrome のサイズ制限内に収める（REF-035）。背景は白 `#ffffff`、本文は `#111827`、主要ボタンは背景 `#1d4ed8` に白文字、エラーは白背景に `#b91c1c` の文字を使う案とする。状態は色だけでなく文字でも示す。ウィンドウの実際のサイズ、拡大表示とキーボード操作は実機で確認する。

画像は縦横比を維持したサムネイルと「画像1」などの識別名で一覧表示し、選択した画像は拡張機能画面内で拡大表示する案とする。画面で `Blob` から object URL を作成し、表示しなくなった画像・画面終了時に解放する。Service Worker では object URL を作成しない（REF-045、REF-046）。画像内容を推測した説明文は付けない。画像データを取得できない場合は失敗を表示し、空の画像として扱わない。

### 4.5 一覧の対象ドメインの選択案

1. 取得した各タスクの正規化済みホストから、現在の PSL を使用して `DomainKey` を求める。`localhost`、IP アドレス、登録可能なドメインを取得できないホストは `host` として完全一致で扱う（ADR-0004、REF-023）。
2. 絞り込み候補は全件と、タスクに対応する重複のない `DomainKey` とする。候補には `value` を表示し、同じ値に異なる種別がある場合は「ドメイン」「ホスト」を添えて区別する。画面から選択した種別と値の両方が一致するタスクだけを表示する。
3. 候補は `value` の UTF-16 コード単位の昇順、値が同じ場合は `kind` の同じ順序で表示する。データの更新後に選択中の対象に該当するタスクがなくなった場合も選択を維持し、「対象なし」と示した候補と絞り込み結果0件を表示する。利用者が全件を選ぶまで、絞り込みを勝手に解除しない。
4. 対象ドメインの判定に失敗した場合はエラーを表示し、全件を判定成功として表示しない。停止設定の対象ホストは、グループを識別する `DomainKey` と区別して扱う。
5. 一覧からドメイン単位の停止を設定する場合、選択した `DomainKey` の `value` を操作の基準ホストとする。例えば `a.example.com` と `b.example.com` が `example.com` に属する場合、`example.com` を基準とする。現在の判定で該当する既存設定がない場合は、この基準ホストを保存する。該当する設定がある場合の変更・解除は、それらすべてに対して行う（ADR-0004）。
6. 停止設定画面に対象ドメインと基準ホストを表示し、判定ルールの更新により将来の停止対象が変わる場合があると伝える。操作時に基準ホストを現在の判定で再計算し、選択された `DomainKey` と一致しない場合は更新せず、一覧の再読み込みを求める。

候補を表示・更新する際のタスク取得と判定結果の一貫性、および基準ホストの再計算と設定変更の間に起こり得る競合の扱いは未決。

### 4.6 停止終了日時の入力案

停止設定画面に端末のタイムゾーンと停止終了の日付・時刻の入力欄を表示する。時刻は分単位で入力し、設定・変更時に選択した瞬間が現在以前の場合は「停止終了日時には、現在より後の日時を入力してください。」と表示して保存しない。解除には日時を入力しない。入力された現地日時が存在しない場合は「この日時は現在のタイムゾーンに存在しません。別の日時を入力してください。」と表示し、保存しない。重複する場合は「この日時は2回あります。どちらかを選択してください。」と表示し、それぞれの UTC オフセットと対応する瞬間を選択肢に示す。どちらも自動選択せず、利用者の選択後に設定する。

候補の提示後に入力または端末のタイムゾーンが変わった場合は、以前の選択を破棄して候補を再計算し、再確認を求める。入力値は保持する。日付・時刻の形式が不正な場合や変換できない場合も理由を表示し、停止設定を変更しない。保存済みの停止終了日時は現在の端末のタイムゾーンで表示し、表示時に分未満の値がある場合も丸めず表示する。

日時変換は `Temporal` の利用を候補とし、詳細と実機検証は DD-task-001 で整理する。日付の入力範囲と、確定操作から保存までの端末設定変更への対応は未決。

### 4.7 キーボード操作案

- 画面を開いたときの初期フォーカスは、登録ではタスク名、一覧では完了状態の絞り込み、編集ではタスク名とする。
- `Tab` / `Shift+Tab` で表示順に操作対象を移動する。ボタンはフォーカスした状態で `Enter` または `Space` により操作する。入力欄での改行や選択操作を妨げない。
- 登録・編集は「保存」ボタンの明示的な操作で確定する。入力中の `Enter` だけで保存しない。撮影、削除、停止設定も対応するボタンの明示的な操作で実行する。
- 削除確認を開いたときは「キャンセル」にフォーカスし、確認を閉じるまで確認内の操作対象を移動する。キャンセル後は元の「削除」に、削除成功後は一覧の見出しか絞り込みにフォーカスを戻す。
- 検証エラー時は該当項目の近くに理由を表示し、最初の不正項目にフォーカスする。保存など項目に限定できないエラーは画面内のエラー表示にフォーカスする。入力値・画像は消去しない。
- `Esc` を含む popup のブラウザ標準操作は上書きしない。画面が閉じた場合の入力復旧は未決であり、上記のフォーカス移動を含め実機で確認する。

### 4.8 編集競合・画面終了時の案

別画面でタスクが更新された場合は、現在の入力を消さず競合を表示し、保存済みの内容を読み直して比較する操作を提供する案とする。再読み込み前に現在の入力が失われる場合は、その旨を表示し、利用者が明示的に確認するまで破棄しない。自動的に上書き・統合しない。元タスクが削除された場合も、入力を保持して削除を通知する。

登録・編集の入力変更時に自動一時保存を要求し、保存中・保存済み・保存失敗を画面に示す。登録済みタスクは明示的な「保存」まで変更しない。保存完了前に画面が閉じた場合、再開時に最後に保存成功した内容を表示する。自動保存が間に合わない入力の復元は保証しない。途中で不正な値も一時保存し、確定時に検証する（DD-task-001）。

一覧画面には進行中の登録・編集を表示し、「再開」と「破棄」を提供する。画面が存在する場合はその画面へ戻る操作を提供する。再開では操作世代を更新し、古い画面の遅延操作を拒否する。破棄では保存済みの途中入力が削除されることを示し、利用者の確認後に実行する。破棄に失敗した場合は途中入力と制限状態を保持し、理由を表示する。操作元の画面が閉じている間に保存結果を確認できなかった場合は、再開時に最後に保存成功した内容を示し、直前の未保存入力が残っているとは表示しない。

進行中は別の登録・編集、完了・未完了、削除、停止設定の変更を実行せず、「登録または編集が進行中です。完了するか破棄してください。」と表示する。一覧表示・絞り込みは引き続き行う。制限の判定は画面上の表示だけでなく保存処理で行う。

## 5. 状態遷移

| 画面・状態           | 契機                 | 次の状態                   |
| -------------------- | -------------------- | -------------------------- |
| 登録・入力中         | 保存成功             | 画面を閉じる               |
| 登録・入力中         | 入力検証・保存失敗   | 理由を表示して入力中に戻る |
| 一覧                 | 編集を選択           | 編集中                     |
| 一覧                 | 削除を選択           | 削除確認中                 |
| 削除確認中           | キャンセル           | 一覧                       |
| 削除確認中           | 削除成功             | 一覧を更新                 |
| 編集中               | 撮影前の一時保存成功 | 対象タブでの操作待ち       |
| 対象タブでの操作待ち | 撮影後に編集を再開   | 編集中                     |
| 編集中               | 保存または取消が成功 | 一覧                       |
| 編集中               | 保存失敗または競合   | 理由を表示して編集中に戻る |
| 登録・編集中         | 画面終了             | 途中入力と操作を保持       |
| 進行中の操作         | 利用者が再開         | 保存済み入力で再開         |
| 進行中の操作         | 利用者が破棄し成功   | 制限を解除                 |

撮影中の取消、popup や Service Worker の停止時の遷移は未決。

## 6. エラー処理

| エラー                         | 検知方法                   | ユーザーへの表示               | ログ           |
| ------------------------------ | -------------------------- | ------------------------------ | -------------- |
| 必須項目・URL・期限の不正      | 入力検証                   | 対象項目と理由                 | エラー種別のみ |
| 画像の件数・サイズ超過         | 件数とバイト数の検証       | 超過した上限                   | エラー種別のみ |
| 一覧・画像の取得失敗           | 保存処理からのエラー       | 取得失敗と理由                 | エラー種別のみ |
| 登録・編集・状態変更の保存失敗 | 保存処理からのエラー       | 保存失敗と理由                 | エラー種別のみ |
| 更新競合                       | 保存処理からの競合エラー   | 競合を表示し、入力を保持       | エラー種別のみ |
| 削除・停止設定の失敗           | 保存処理からのエラー       | 操作が完了していないことと理由 | エラー種別のみ |
| 撮影・一時保存の失敗           | 撮影・保存処理からのエラー | 撮影できなかった理由           | エラー種別のみ |

画面が閉じている間に発生したエラーの通知方法は未決。

## 7. ログ出力

エラー種別のみを記録し、タスク名・詳細・URL・ホスト・画像・停止設定をログに出力しない。

## 8. テスト観点

- 正常系: ショートカットからの登録、期限・詳細・画像の任意入力、一覧の並び替えと複合絞り込み。
- 正常系: URL 変更時のドメイン再計算、画像追加・個別削除・差し替え、完了・未完了の切り替え。
- 正常系: 削除の確認・キャンセル、タスク単位とドメイン単位の停止設定・変更・解除。
- 異常系: 入力不正、取得・保存・削除失敗、画像の差し替え失敗、編集の更新競合。
- 境界値: 現地日付の前日・当日・翌日の期限、完了済みと期限なし、画像10枚・11枚、5,000,000バイト・5,000,001バイト。
- セキュリティ: 入力や画像が閲覧ページ・content script・ログに露出しないこと。
- 操作: キーボードのみでの入力・保存・削除確認とフォーカス移動、入力欄の `Enter` による意図しない保存の防止。
- 表示: 取得失敗と0件の区別、検証エラーの対象項目、撮影と復元の両方の失敗。
- 一覧: 期限・登録日時が同じタスクの再表示時の順序、対象ドメインの種別と値の照合、選択中の候補にタスクがなくなった場合。
- 停止設定: 該当する既存設定がない場合に一覧で選択した対象ドメインの値が基準ホストとして保存されること、判定ルール更新後に基準ホストから停止対象を再計算すること。
- 停止設定: 存在しない現地日時の再入力、重複時のオフセット選択、入力または端末のタイムゾーン変更後の再確認。
- 停止設定: 分単位の時刻入力、終了日時が保存時の現在以前の場合の拒否、解除時に日時を要求しないこと。
- 編集: 競合時に現在の入力を勝手に上書き・破棄しないこと、再読み込み前に破棄の確認があること。
- 登録・編集: 同時開始の片方を拒否し、制限中も一覧を表示できること。画面終了・Chrome 停止後の再開・破棄と、保存前に閉じた入力の扱い。
- 表示: popup のスクロール・拡大表示、画像プレビューの取得失敗と object URL の解放、状態が色だけに依存しないこと。
