# TS-002 タスク管理と端末内保存

## 1. テスト対象と範囲

タスク一覧・編集・状態変更・削除、画像の編集、IndexedDB の保存・復旧と容量を対象とする。停止設定の操作と日時判定は TS-003 で扱う。本書は案であり、移行を中止した旧形式の一時データの復旧操作は未確定である。

## 3. 手動テストとする理由

No.13、22 は Chrome の終了・再起動とプロファイルの保持を実際に確認するため手動とする。自動化する場合も同一プロファイルでブラウザプロセスを終了・再起動し、結果を再確認する。

## 4. テストデータ

- 一覧順序用: A は期限 `2026-11-24`・登録 `2026-11-01T00:00:00.000Z`、B は同期限・登録 `2026-11-02T00:00:00.000Z`、C は期限 `2026-11-25`、D・E は期限なしで D の登録日時が E より古い。
- 容量用: DD-task-001 の定義に従い、タスクの各フィールドを指定順に JSON 化した UTF-8 バイト数と、画像の識別情報・順序の JSON の UTF-8 バイト数および Blob のバイト数を合計する。1タスク10枚以下・1枚5,000,000バイト以下で、詳細の ASCII 文字を調整し合計をちょうど100,000,000バイトにする。
- 保存前後のタスク、画像の ID・順序・バイト内容と容量を記録し、実データは使用しない。

## 5. カバーできていない要件

- 端末故障や Chrome のデータ消去を除く長期間の保持は、再起動試験だけでは証明できない（NFR-AVL-002）。
- DB の旧形式の一時データを確認・復旧する操作、入力文字数の上限は未確定。確定後に対応するケースを追加する（DD-task-001、DD-task-002）。
