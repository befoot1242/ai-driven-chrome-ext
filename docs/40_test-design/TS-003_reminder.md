# TS-003 リマインドと停止設定

## 1. テスト対象と範囲

対象ドメイン判定、ページ遷移、独立画面、タスク・ドメイン単位の停止設定および日時を対象とする。実際の画面数・内容を確認し、空の余分な画面も重複として扱う。画像撮影は TS-001、性能と情報露出は TS-004 で扱う。

本書は案であり、Worker 停止後の二重画面防止、初回 URL が不明な場合の復旧および停止設定の一部の競合制御は未確定である。

## 3. 手動テストとする理由

該当なし。Worker の停止時点と物理的なウィンドウ数を E2E で観測できる手段は未確定である。観測手段を検証できない場合は No.19 を合格とせず、手動で補助確認しても網羅的な証明としない（REF-048、REF-049）。

## 4. テストデータ

- テスト専用の HTTP・HTTPS ページ、未完了・完了タスクおよび停止設定を用意する。実利用データは使わない。
- No.15〜17 は時刻を固定して検証し、実際の時計に依存して過去日時の拒否と夏時間の判定を混同しない。タイムゾーン変更の実機動作は別に確認する。
- ウィンドウの作成・終了・対応元タブと試験操作の時系列を記録する。終了条件を確認できない観測を「画面がなかった」とみなさない。

## 5. カバーできていない要件

- 未確定の停止・復旧方法および初回 URL 不明時の通知は具体的な画面操作・期待結果を確定できない。実機試験が不可能な場合または失敗した場合は設計に差し戻す（DD-reminder-001）。
- 有限の Worker 停止試験では、あらゆる停止タイミングで重複がないことを証明できない。
- 停止終了日時の入力可能範囲、候補確定から保存までの端末設定変更は未決（DD-task-001、DD-task-002）。
