# TS-004 性能・情報保護・通信と対応環境

## 1. テスト対象と範囲

リマインドの表示時間、タスク情報の端末外送信・ページ露出、通信の送信元と切断、および対応ブラウザを対象とする。データ保持は TS-002 で扱う。本書は案であり、性能の共通時間基準と描画完了の取得、送信元・操作の対応付け、情報露出の網羅的な観測は未確定である。

## 3. 手動テストとする理由

No.1 は独立画面を含む同一時間基準の取得と実際の描画点の観測方法が未検証のため手動とする。No.9 は確認時点の Chrome 最新版と、実際のブラウザでの受け入れ基準を確認するため手動とする。自動化しても、使用ブラウザが Google Chrome の最新版であることと、実際の画面が観測できることを確認する（REF-053）。

## 4. テストデータ

- No.1 は対象ドメインの未完了100件、別ドメインの未完了100件で画像なし。CPU・メモリ・Windows と Chrome のバージョン、各操作・対象・開始と終了の根拠・測定値を記録する。
- No.2、8 は実データを使わず、他の通信と識別できる固有のテスト用タスク名・詳細・URL・画像を使う。通信の送信先・リクエスト・ページ DOM・ページ向けメッセージを観測し、平文、URL エンコード、Base64、JSON やバイト列を含めて照合する。観測・復元できない経路があれば記録する。
- 確認のためのトレースやログには実利用者の情報を含めない。拡張機能が送信した通信と、テストページ自体による通信を区別する。

## 5. カバーできていない要件

- No.1 は開始・終了点と共通の時間基準、トレースから独立画面の描画を確認する方法が未確定。`webNavigation` の `timeStamp` と `Date.now()` を直接比較せず、`requestAnimationFrame` や DOM 更新を単独で描画完了の証拠としない。方法を確認できなければ NFR-PERF-001 は未検証（REF-013、REF-052、DD-reminder-001）。
- No.2 はネットワークとページへの受け渡しを観測する範囲・方法の網羅性が未確定。観測できない経路を0件と扱わない。No.4〜7 の所有者確認・結果照合と通知の具体的方法も未決（DD-communication-001）。
- 有限のケースで全ブラウザの状態やすべての外部送信経路が存在しないことまでは証明できない。NFR-CMP-001 の対象は確認時点の Chrome 最新版である。
- No.10、11 の所有者確認とストリーム ID の観測方法は未確定。試験の観測・記録に実利用者の情報やストリーム ID を残さない。
