# ADR-0004 対象ドメイン判定に PSL を使用する案

## 状況

サブドメインをまとめつつ、`example.co.jp` と `other.co.jp`、共有サービス上の異なる利用者のサイトを区別する必要がある。

## 決定

共有サービスを含む Public Suffix List（PSL）を同梱し、対象ドメイン判定に使用する案とする。PSL はサイトのグループ化に利用できるが、ルールにはワイルドカードや例外がある（REF-015、REF-016）。単純に末尾2ラベルを比較する方式では要件を満たせない。

利用者が選択した `tldts` を候補とする。URL は標準の URL パーサーで正規化した後に判定し、`allowPrivateDomains: true` と `extractHostname: false` を使用する案とする。共有サービスの判定には前者の指定が必要である（REF-023）。

採用する `tldts` のバージョンを固定し、更新時に PSL も更新する。確認時点の候補は `tldts` 7.5.5 とする。この版は `tldts-core` に依存し、両パッケージのライセンス表記は MIT である（REF-028、REF-029）。PSL の元データは MPL 2.0 であり（REF-024）、生成データを含めた実際の同梱物と配布条件の確認は未了。サブドメイン、共有サービス、IP、ドメインを取得できないホスト、および PSL 更新後の停止設定を検証する。

判定情報は拡張機能の更新時に更新し、タスクは現在の判定情報で再判定する。ドメイン単位の停止は設定時の基準ホストを記録し、現在の判定情報で停止対象を再計算する。実行時にタスクデータ・画像を外部送信しない。`localhost` と IP アドレスはホスト完全一致とする。

ライブラリで登録可能なドメインを取得できないホストも、正規化後のホストが完全一致する場合のみ同じ対象とする。

複数のドメイン停止設定が同じ対象に該当する場合は、最も遅い終了日時まで停止する。個々の設定を保持し、現在の判定情報で判定する。停止期間の変更・解除は、現在の判定で対象に該当する設定すべてに対して行う。

## 結果

- PSL の更新が拡張機能の更新まで反映されないため、判定情報が古くなる可能性がある。
- `tldts` 本体は MIT ライセンス（REF-025）、PSL の元データは MPL 2.0（REF-024）である。同梱物と配布条件の確認は未了。
- 採用版の最終確認、依存先の固定、生成データを含めた配布条件の確認は未決。
